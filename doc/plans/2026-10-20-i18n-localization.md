# 需求文档:UI 国际化多语言切换(i18n)

- 日期:2026-10-20
- 状态:首期实现与验证中，核心中英文链路已迁移；其余专门页面按 P2 继续推进
- 范围:`ui/` 为主；核心流程缺少稳定错误码时同步补后端契约；跨设备偏好另行迭代

## 1. 需求背景与目标

当前 UI 大部分文案为硬编码英文，已有少量国际化接入。目标是提供个人界面语言切换，首发开放简体中文（zh-CN）、English（en）和“跟随浏览器”，再逐步发布其他语言。

目标(按优先级):

1. 用户可在设置中切换界面语言,选择持久保存,刷新后保持。
2. 界面文案、日期、数字、货币等展示随语言变化。
3. 新语言通过翻译、校验和发布清单扩展，不需要修改业务组件。
4. 不破坏现有视觉设计(token 规则、术语表规范)。

非目标(本期不做):

- RTL(阿拉伯语等)完整适配——本期只开放 LTR 语言。
- 服务端渲染/邮件等 UI 之外的多语言。
- 文档内容(issue 正文、评论等用户生成内容)的翻译。
- 改变 Agent 回复语言、系统提示词或技能内容；界面语言与任务输出语言分别管理。

## 2. 现状摸底(2026-10-20 调查结论)

以下为实施前基线。当前已加入语言选择、个人浏览器偏好、发布语言清单、格式化与核心页面资源；实现和验证以本次 Git diff、测试及实际页面证据为准。首期不宣称全部历史界面已完成翻译。

### 已有基建(可复用,勿重造)

- `ui/src/i18n/index.ts`:i18next v26 + react-i18next v17 已初始化,但 `lng` 硬编码 `DEFAULT_LOCALE`("en"),无 `changeLanguage` 调用点,无语言切换器。
- `ui/src/i18n/locales.ts`:用 `import.meta.glob` eager 打包 40 个 locale JSON(含 zh-CN/zh-TW)。
- `ui/src/i18n/locale-validation.ts`:已有安全校验(禁 `<script>`、禁裸 HTML、插值占位符必须与 en 一致)及配套测试,新增语言直接复用。
- `ui/src/App.tsx` 已有 `useTranslation` + `t(key, { defaultValue })` 使用范例。
- 主题偏好模式可借鉴:`ui/src/context/ThemeContext.tsx`(localStorage + Context)。

### 差距

| 项目 | 现状 |
|---|---|
| 文案覆盖 | 40 个 locale JSON 实际各 3 条 key；App.tsx 还有仅提供 defaultValue 的文案，大部分业务界面仍为英文 |
| 语言切换 | 无切换器、无持久化、无 `changeLanguage` 接线 |
| 格式化 | `ui/src/lib/utils.ts` 的展示格式化硬编码 `"en-US"`；其他文件存在直接格式化调用、英文相对时间和时长单位 |
| 持久化 | 无 locale 相关 DB 字段或 API;有 `user_sidebar_preferences` 表范式可参考 |
| 打包 | 40 个 locale eager 打进主 bundle,文案增多后需拆分 |
| 校验 | 启动时校验全部语言与英文 key 完全一致；只扩充 en/zh-CN 会使其余语言校验失败，defaultValue 不能修复启动失败 |
| 错误提示 | 部分页面直接展示 ApiError.message；需要稳定错误码映射，不能靠英文字符串匹配完成翻译 |

### 约束(必须遵守)

- `DESIGN.md` Principle 7 术语表:同一概念全 UI 只能用一个词(canonical term 为 *task*,禁 *issue/ticket*)。key 命名与译文必须遵守;替换文案属于可见变更,需审查。
- Token-only 规则:语言切换器等新 UI 的颜色/间距/字号必须来自 `ui/src/index.css` token 层;提交前跑 `pnpm check:token-gates`。
- 测试保留默认英文环境；核心流程以真实翻译资源验证中英文。不要统一 mock 为 key，以免掩盖缺文案、插值和切换不重渲染的问题。
- 现有字体 token 已有系统字体回退。首期验证中文、长英文和窄屏布局；确有问题再在 token 层修复，不在组件中写视觉常量。

## 3. 设计方案

复用现有 `ui/src/i18n/` 体系（i18next），按以下里程碑落地。P0 是基础设施完成，P1 才是核心链路可用；不能将少量文案变化称作全站国际化。

### P0 语言状态和资源发布

- 主入口：个人设置 → 语言与显示；账户菜单提供快捷入口，登录页和无公司页也能切换。语言名用自称“简体中文 / English”，不使用国旗。
- 用发布清单只注册 en/zh-CN；其他 38 种资源作为未发布语言保留。保留 key、插值和 HTML 安全校验，并补充按语言的复数规则校验；有复数时比较语义 key 覆盖及各语言所需分支，不能要求中文与英文复数后缀完全相同。翻译缺失不静默发布。
- `i18n` 是生效语言的唯一来源。偏好 hook 管理 `auto | en | zh-CN`，持久化键按实例/用户隔离；未登录使用浏览器级偏好。切换公司保持当前语言，切换账号重新读取对应偏好。
- 优先级：明确选择 > 浏览器支持的语言 > en；首期简体中文语言匹配规则写入测试，未发布语言按规则回退，不显示在选择器中。
- 首屏渲染前初始化，更新 HTML lang；跨标签页同步；存储不可用时内存降级。异步资源加载失败时保留原生效语言与草稿，给出可重试提示。
- 展示用格式化统一封装，并让调用组件订阅语言变化；更新 memo、状态标签和面包屑依赖，避免只读取全局变量却不重渲染。

产出：语言状态、发布策略、格式化与切换机制可用；开始批量迁移前先验证此闭环。

### P1 核心使用链路完整双语

- 覆盖登录、公司选择/创建、导航、首页、任务列表/详情/创建/编辑、Agent 配置、AI 连接/网关配置、个人设置。
- 每条链路同时迁移空态、加载、表单校验、通知、确认文案、tooltip 和无障碍标签。
- 按 common、navigation、tasks、agents、connections、settings、errors 等业务域组织资源；使用语义 key，如 `tasks.empty.title`。UI 统一使用“任务”，API 的 issues 等标识不变。
- 提取脚本只生成候选清单/机械改动，按业务批次审查。避免拼接句子，用插值和复数规则；迁移批次同时提交 en/zh-CN。defaultValue 仅作旧页面过渡兜底。
- 已有稳定 code 映射为本地文案；新网关错误从首版提供 code + 安全参数。旧接口缺 code 时分批补齐，未知错误显示本地化通用提示并保留安全的诊断标识，不能匹配英文 message 翻译。

### P2 全站覆盖与新增文案门禁

- 扩展审批、费用、技能、连接市场和运维等剩余界面，记录已覆盖路由和未迁移范围。
- 将展示用日期、数字、金额、相对时间、时长和单位收口；历史原始日志与第三方返回内容保留原文。
- 只迁移展示格式，禁止机械替换全部 en-US：例如 `cron-fires.ts` 用英文星期参与计算，必须保持确定性。
- 金额保留原有 currency 和 cents 语义，中文不代表人民币；语言切换不改变时区、UTC 预算周期或任务调度规则。
- 按已迁移路径增加新增硬编码文案检查，避免要求一次清理整个仓库。资源加载按发布语言拆分；文案增长时按业务域动态加载。

### P3 跨设备与其他语言（后续）

- 跨设备同步使用本人可读写的实例级 `user_preferences`，保存 localePreference；参考侧栏偏好的鉴权模式，不把语言塞进侧栏表或增加公司覆盖。
- 登录后服务端偏好为权威，本地缓存用于首屏；保存失败保留明确可见的未同步状态。
- 其他语言完成翻译、插值/复数校验、布局验证后加入发布清单。RTL 另行验证后开放。

## 4. 验收标准

1. P1 核心链路全部双语；P2 覆盖全站系统文案。切换无需刷新，表单草稿、当前路由与任务会话保留。
2. 刷新保存、跟随浏览器、未支持语言回退、跨标签页、账号切换、存储失败均有验证。
3. 使用真实语言资源验证插值、复数、错误码、日期/金额/相对时间；保留 cron 与预算语义的回归覆盖。
4. 中文、长英文、窄屏、键盘操作和 HTML lang 验证通过；术语遵守 DESIGN.md。
5. 实现时运行最小相关测试和 `pnpm check:token-gates`；PR-ready 前完成 `pnpm -r typecheck`、`pnpm test:run`、`pnpm build`，未运行项目明确报告。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 提取脚本误改/漏改,产生半翻译界面 | `defaultValue` 兜底;分批小 PR;提取结果人工抽查 |
| 只扩充中英文导致启动失败 | P0 先引入发布语言清单，未发布资源不参与运行时全量校验 |
| 测试失去实际翻译覆盖 | 保留默认英文测试，并增加真实资源下的中文切换行为测试 |
| bundle 体积膨胀 | 仅发布两种语言，按语言和业务域分包 |
| 中文或长文案布局异常 | 首期覆盖字体回退、弹层、菜单与窄屏，必要修改仅在 token 层 |
| 术语不一致(翻译引入 issue/task 混用) | key 命名绑定术语表;翻译校对时按术语表检查 |
